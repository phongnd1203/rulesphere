## Có thể gom lại thành 15 top-level Use Cases

Nếu mục tiêu là **Use Case Diagram**, không nên vẽ 200 ellipse. Danh sách chi tiết phía trên phù hợp làm **Use Case Catalog / Functional Requirements decomposition**. Use Case Diagram cấp hệ thống nên gom thành:

```text
UC-01  Manage Decision Projects
UC-02  Author Decision Models
UC-03  Manage Business Rules
UC-04  Manage Decision Data Contracts
UC-05  Validate Decisions
UC-06  Test Decisions
UC-07  Manage Decision Versions
UC-08  Review and Approve Decision Changes
UC-09  Build and Publish Decision Artifacts
UC-10  Manage Decision Deployments
UC-11  Execute Decisions
UC-12  Explain Decision Results
UC-13  Simulate and Analyze Decisions
UC-14  Monitor Decision Operations
UC-15  Audit Decision Lifecycle
UC-16  Manage Users and Access
UC-17  Manage Client Applications
UC-18  Integrate CI/CD Automation
UC-19  Manage Platform Configuration
```

Tôi đề xuất **19 top-level use cases** này làm mức abstraction chính cho System Use Case Diagram. Các UC chi tiết ở catalog phía trên sẽ trở thành `include`, `extend`, hoặc functional requirements dưới từng top-level UC.

### Actors tương ứng

Có thể chuẩn hóa actor model thành:

```text
Human Actors
- Rule Author
- Reviewer
- Approver
- Tester
- Release Manager
- Business / Decision Analyst
- Operator
- Auditor
- Developer
- Project Administrator
- Platform Administrator

External System Actors
- Client Application
- CI/CD System
- Identity Provider
- Monitoring / Observability System
- Event / Webhook Subscriber
- Decision Runtime Node
```

Một điểm cần giữ rất rõ khi đưa vào SRS: **Business Process User / BPM Engine không điều khiển process bên trong RuleSphere**. Một BPM engine có thể xuất hiện như một `Client Application` gọi:

```text
Business Process
      |
      | Decision Request
      v
+--------------------+
|     RuleSphere     |
| Execute Decision   |
+--------------------+
      |
      | Decision Result
      v
Business Process
```

RuleSphere quyết định **“What decision should be made?”**, còn process/workflow engine quyết định **“What happens next?”**. Đây là boundary quan trọng để tránh scope creep của RuleSphere.
