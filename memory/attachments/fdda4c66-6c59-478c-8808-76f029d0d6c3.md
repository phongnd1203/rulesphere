## Recommended names for the actual Context Diagram

For the diagram itself, **57 arrows would be too detailed**. I would consolidate closely related flows while still keeping each arrow semantically meaningful:

```text
Rule / Decision Author
  → RuleSphere: Rule Development Data
  → RuleSphere: Validation & Testing Request
  ← RuleSphere: Rule Development Result

Reviewer / Approver
  → RuleSphere: Review & Governance Decision
  ← RuleSphere: Review & Governance Information

Platform Administrator
  → RuleSphere: Platform & Access Configuration
  ← RuleSphere: Administration Information

Operations / SRE
  → RuleSphere: Deployment & Operational Control
  ← RuleSphere: Deployment & Runtime Status

Decision Consumer
  → RuleSphere: Decision Request Data
  ← RuleSphere: Decision Response Data

Identity Provider
  ← RuleSphere: Authentication & Identity Request
  → RuleSphere: Identity & Authentication Data

CI/CD & Automation
  → RuleSphere: Automation Request
  ← RuleSphere: Automation Result

Observability Platform
  ← RuleSphere: Observability Data
  → RuleSphere: Monitoring Request

Audit / SIEM
  ← RuleSphere: Audit & Security Event Data
  → RuleSphere: Audit Request
```

The key naming principle is to use **noun phrases representing data**, rather than actions. For example, prefer **“Deployment Request”** over “Deploy Rule”, **“Decision Result”** over “Return Decision”, and **“Rule Development Data”** over “Create/Edit Rule”. This is more correct for DFD notation.
